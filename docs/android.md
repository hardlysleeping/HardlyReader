# Android builds (debug APK for a tablet)

HardlyReader is a Tauri 2 app, so the Android target is a normal Tauri mobile
project under `src-tauri/gen/android` (generated by `tauri android init`, not
hand-maintained).

Current output on this machine:

```
src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

That is a **universal debug APK**: `arm64-v8a` + `armeabi-v7a`, package
`ing.hardlysleep.hardlyreader`, minSdk 24, targetSdk 37, signed with the Android
debug keystore. Debug builds are big (~330 MB) because they carry both ABIs,
unoptimized Rust and JNI debug symbols — that is expected, not a packaging bug.

## One command

```bash
scripts/android-build.sh            # debug APK, arm64 + armv7
TARGETS="aarch64" scripts/android-build.sh
```

The script is idempotent: it installs the NDK / SDK platform / rust targets /
`gen/android` only if they are missing, applies the gradle template fix below,
then builds. It runs the build inside the **Arch distrobox** (the host has no
pnpm or cargo toolchain) and tees the log to
`~/.hermes/cache/scratch/android-build.log`.

Equivalent manual command:

```bash
distrobox enter Arch -- bash -lc '
  cd <repo>
  export JAVA_HOME=$JAVA_HOME   # a JDK 17
  export ANDROID_HOME=$ANDROID_HOME
  export NDK_HOME=$ANDROID_HOME/ndk/<version>
  export PATH=$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$HOME/.cargo/bin:$PATH
  ./node_modules/.bin/tauri android build --apk --debug --target aarch64 --target armv7
'
```

First run downloads Gradle 9.6.1 plus the Android/JetBrains dependencies (roughly
1 GB) and takes 10–20 minutes; later runs are minutes. Build it in the background
and poll the log rather than letting a tool call time out.

## Prerequisites

| Piece | Value used here |
| --- | --- |
| JDK | Temurin 17 — `~/.local/java/jdk-17.0.20.1+1` |
| Android SDK | `~/Android/sdk` (`cmdline-tools/latest`, `platform-tools`, `build-tools;37.0.0`, `platforms;android-37.0`) |
| NDK | `27.2.12479018` (`~/Android/sdk/ndk/27.2.12479018`) |
| Rust | rustup (not the distro `rust` package) with `aarch64-linux-android`, `armv7-linux-androideabi`, `i686-linux-android`, `x86_64-linux-android` |
| Node/pnpm | inside the Arch distrobox |

Install the missing bits with:

```bash
$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --install "ndk;27.2.12479018" "platforms;android-37.0" "build-tools;37.0.0"
yes | $ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --licenses
curl https://sh.rustup.rs -sSf | sh -s -- -y --no-modify-path   # inside the distrobox
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

Environment variables the build must see:

```
JAVA_HOME=$HOME/.local/java/jdk-17.0.20.1+1
ANDROID_HOME=$HOME/Android/sdk
NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018
PATH=$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$HOME/.cargo/bin:$PATH
```

## Install on the tablet

Enable USB debugging, plug it in, then:

```bash
adb devices
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

`-r` reinstalls over an existing copy. A debug APK and a release APK **cannot**
replace each other: different signing keys, so `adb uninstall
ing.hardlysleep.hardlyreader` first when switching. Check what is installed with
`adb shell dumpsys package ing.hardlysleep.hardlyreader | head`.

Verify an APK without a device:

```bash
$ANDROID_HOME/build-tools/37.0.0/aapt2 dump badging <apk> | head -4
$ANDROID_HOME/build-tools/36.0.0/apksigner verify --print-certs <apk>
```

## Known template gap: the gradle rust task

`tauri android init` generates
`src-tauri/gen/android/buildSrc/src/main/java/<identifier path>/kotlin/BuildTask.kt`
containing:

```kotlin
val args = listOf("tauri", "android", "android-studio-script");
```

The task runs with `cwd = src-tauri`, and node resolves a bare `tauri` argument
as a *file path*, not a module, so every `rustBuild*Debug` task fails with:

```
Error: Cannot find module '<repo>/src-tauri/tauri'
    code: 'MODULE_NOT_FOUND'
> Execution failed for task ':app:rustBuildArm64Debug' (registered by plugin 'rust').
```

Fix — point it at the CLI entry that actually exists on disk:

```bash
CLI_JS=$PWD/node_modules/@tauri-apps/cli/tauri.js
sed -i "s|listOf(\"tauri\", \"android\", \"android-studio-script\")|listOf(\"$CLI_JS\", \"android\", \"android-studio-script\")|" \
  $(find src-tauri/gen/android/buildSrc -name BuildTask.kt)
rm -rf src-tauri/gen/android/buildSrc/build src-tauri/gen/android/.gradle/configuration-cache
```

`scripts/android-build.sh` does this automatically whenever the unpatched line is
present, so re-running `tauri android init --force` is safe.

## Version codes

`src-tauri/gen/android/app/tauri.properties` is generated from
`src-tauri/tauri.conf.json`: version `0.1.0` becomes `versionName=0.1.0`,
`versionCode=1000`. Android refuses an update whose `versionCode` is not higher
than the installed one, so bump the app version before shipping an update.

## Release APKs and signing

A release APK/AAB needs its **own keystore**, and Android only accepts an update
if it is signed with the *same* key as the installed version. Lose the keystore
and every existing install must be uninstalled before the new build can be
sideloaded.

Rules:

- Keep the keystore file and its passwords **outside this repo** (e.g. under
  `~/.android-keys/`), never in `src-tauri/` or `src-tauri/gen/android/`.
- Never commit `key.properties`, `*.jks` or `*.keystore`; `.gitignore` already
  covers them.
- Wire the signing config through environment variables, not literals, e.g. in
  `src-tauri/gen/android/app/build.gradle.kts`:

```kotlin
android {
  signingConfigs {
    create("release") {
      storeFile = file(System.getenv("ANDROID_KEYSTORE_PATH") ?: error("ANDROID_KEYSTORE_PATH unset"))
      storePassword = System.getenv("ANDROID_KEYSTORE_PASSWORD")
      keyAlias = System.getenv("ANDROID_KEYSTORE_ALIAS")
      keyPassword = System.getenv("ANDROID_KEYSTORE_KEY_PASSWORD")
    }
  }
  buildTypes { getByName("release") { signingConfig = signingConfigs.getByName("release") } }
}
```

- Generate one (once, and back it up):

```bash
keytool -genkeypair -v -keystore ~/.android-keys/hardlyreader-release.jks \
  -alias hardlyreader -keyalg RSA -keysize 4096 -validity 10000
```

- Then `scripts/android-build.sh --release` after exporting
  `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_ALIAS`,
  `ANDROID_KEYSTORE_PASSWORD` (and `ANDROID_KEYSTORE_KEY_PASSWORD`).

Release mode also flips the Rust profile to the `[profile.release]` settings in
`src-tauri/Cargo.toml` (LTO, `opt-level=3`, stripped), which gives a far smaller
APK than the debug one.

If the 330 MB debug APK is awkward to sideload over `adb`, the bulk is JNI debug
symbols (`libhardlyreader_lib.so` is ~181 MB for arm64 alone). Adding
`strip = true` under a `[profile.dev]` table in `src-tauri/Cargo.toml`, or
shipping a release build, brings the APK down to a few tens of MB.

## Release build and signing

The generated gradle project has **no** release `signingConfig`, so `tauri android build`
produces `.../apk/universal/release/app-universal-release-unsigned.apk`. That is expected; sign it
afterwards:

```sh
BT=$(ls -d "$ANDROID_HOME"/build-tools/* | sort -V | tail -1)
UNSIGNED=$(find src-tauri/gen/android/app/build/outputs/apk -name '*-release-unsigned.apk' | head -1)
SIGNED="${UNSIGNED%-unsigned.apk}.apk"
"$BT/zipalign" -p -f 4 "$UNSIGNED" "$SIGNED.aligned"
"$BT/apksigner" sign --ks "$ANDROID_KEYSTORE_PATH" --ks-key-alias "$ANDROID_KEYSTORE_ALIAS" \
  --ks-pass env:ANDROID_KEYSTORE_PASSWORD --key-pass env:ANDROID_KEYSTORE_PASSWORD \
  --out "$SIGNED" "$SIGNED.aligned"
"$BT/apksigner" verify --print-certs "$SIGNED" | head -4
```

`scripts/android-build.sh --release` does this for you, given three env vars:

| variable | meaning |
|---|---|
| `ANDROID_KEYSTORE_PATH` | the `.jks` file, **outside the repo** |
| `ANDROID_KEYSTORE_ALIAS` | the key alias inside it |
| `ANDROID_KEYSTORE_PASSWORD` | the store and key password (passed to `apksigner` by env *name*, never as an argument) |

**The keystore is the identity of the app.** An APK only installs over an existing one with the
same signature, so losing the keystore means every user has to uninstall before updating — keep a
copy somewhere that is not this machine, and never commit it (`*.jks`, `*.keystore`,
`keystore.properties` are already ignored). A *debug*-signed APK cannot be updated by a
release-signed one and vice versa: pick one for the install you keep.
